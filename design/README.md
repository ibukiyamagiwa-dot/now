# 設定資料集（design/）

世界観、作風、敵キャラ一人一人の立ち絵・モーション・設定をまとめる資料集の、ソースと決まったこと。資料集づくりは専用のチャットで進める。

## まず読むもの
- `DECISIONS.md`：決まったこと（原則、作風、世界観、全員に通じる決まり、敵の系統と強さの順、進める順番）。新しいチャットは最初にこれを読む。
- どの組が確定したか（ゲームに入れてよいか）は、`DECISIONS.md` の「確定した組」の表を見る。
- `chars/`：敵の組ごとの細部（見た目・技・モーション・パリィされ・ブレイクなど）と主人公。作業する敵のファイルだけ読めばよい。

## フォルダ
| 場所 | 中身 |
| --- | --- |
| `bible/` | 初版「門の番人たち 八つの姿」。骨組み（`rig.js`）から全員を描く。`python3 build.py` で `bible.html` を作る（1ファイル、外部なし） |
| `v2/` | 第2版（決まった作風）。`python3 build2.py` で `bible2.html`。いまは主人公と門の系統。 |
| `v2/`（旧） | 作風を決めたあとの試し描き。頭身を格で変える（主人公 約3、門番 約3.3、ボス 約4）。兜の作りこみ、新しい主人公。`t.html` をブラウザで開くと見られる |
| `style/` | 作風A・B・Cの書き比べ（`sheet.html`、結果は `style_compare.png`）。結論：どれも違い、初版の雰囲気＋Bの等身に決まった |
| `old/` | 比較用に切り出した、いまのゲームのボスの絵 |

## 骨組みのしくみ（bible/ と v2/ 共通）
- `engine.js`：ドットを置く土台（多角形・円・太線・触手、自動の輪郭線）
- `rig.js`：騎士の骨組み。姿勢 `P`（関節の角度）と設計 `S`（色・兜・武器・マント・飾り）から描く。角度は画面の向き（0＝右、π＝左）
- `specs.js`：8つの姿の設計。色と部品には、すべて意味を書いている
- `motion.js` `moves.js`：モーション＝キーの並び。合図の光（`cues`）と当たり（`hits`）は、合図から28Fで当たるように置く（打ち合いは別）
- `stages.js`：専用ステージ（240×135）
- `hurt.js`（v2）：全員の「やられ」、足りなかった出現、モーションの種類（出現・待機・攻撃・やられ・撃破）の分け方
- `boar.js` `mobs.js` `shade.js` `iai.js` `imp.js`（v2）：中ボスとモブ。`boar.js` は四つ足の骨格、`mobs.js` は中ボスとモブの設計とモーション、`shade.js` は影の剣士、`iai.js` は居合の剣士、`imp.js` は石なげ小鬼
- `content.js` `page.js` `shell.html`：資料集ページの文章とつくり
- `audit_stance.py`（v2）：いちばん大事な原則の点検。同じ敵の技で、一度に来る数や間がちがうのに、予兆の瞬間の絵がほぼ同じ組を出す。例外の表で除いて、残れば終了コード1（`python3 audit_stance.py [組…] [-v]`、組は `門` `赤` `竜` などか敵の key）
- `audit_stage.py`（v2）：ステージの明るさの点検。覚悟の段ごとに敵と主人公を背景に立たせ、輪郭の差と合図の余白を見る。不合格があれば終了コード1（`python3 audit_stage.py [組…]`）
